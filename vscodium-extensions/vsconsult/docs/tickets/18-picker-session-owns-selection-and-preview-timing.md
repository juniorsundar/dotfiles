# 18 — PickerSession owns Selection and Preview timing

**What to build:** Move canonical Selection and Preview coordination into PickerSession. The session is authoritative for Selection: it validates that a selected Candidate belongs to the current visible result set, applies wrap-around and first-selection rules, preserves a valid selection across compatible result updates, and falls back deterministically when the selected Candidate disappears after a query or stream change. Keyboard navigation reaches the session as navigation intent (relative and boundary movement), and click selection reaches it as a Candidate id; absolute row indexes do not cross the adapter boundary. The session owns the Preview debounce timer and a Preview generation: on settle it emits a typed Preview request carrying the current Candidate and operation token. PickerHost executes the Preview through the narrow Picker context and dispatches typed success or failure back to the originating active session. Preview failure is non-fatal. Presentation outputs now carry the canonical selected Candidate id alongside rows, so the Shared view renders selection rather than deciding it; the view continues to send select messages, but the host forwards them as navigation intent rather than trusting the view's chosen index. The existing webview selection behavior is preserved by rendering the session's canonical selected id. Stale Preview completion (a delayed preview from an old Selection) is ignored by Preview generation. Behavior is unchanged for the user: navigation, wrap, preview, and stream-driven selection recovery all feel the same.
