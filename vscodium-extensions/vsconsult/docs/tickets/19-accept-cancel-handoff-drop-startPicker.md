# 19 — Session-driven Accept and Cancel; explicit Handoff; drop startPicker

**What to build:** Move Accept, Cancel, and chooser replacement into the PickerSession/PickerHost contract and remove the implicit PickerContext.startPicker control flow. PickerSession emits a typed Accept request for the canonical Selection; PickerHost executes the Picker's Accept through the narrow Picker context and reports the outcome back to the active session. Completion remains the default Accept outcome — ordinary pickers may still return no explicit result and successful return completes the Host interaction. A picker may instead explicitly return a Handoff naming the next registered Picker id; the picker chooser preserves its current behavior by returning Handoff(candidate.id) from Accept instead of calling PickerContext.startPicker. On Handoff, PickerHost disposes the outgoing session's source, timers, and virtual preview, starts the destination Picker session, and preserves the current Host interaction and its Return context — it does not run Cancel, restore the Origin, restore Panel visibility, or recapture Return context between sessions. Return context (Origin and prior Panel visibility) is captured once per Host interaction, preserved across Handoff, and consumed only on final Accept or Cancel. The picker-chooser startPicker primitive is removed from PickerContext; session control is no longer an editor-effect helper. Accept failure and Handoff failure are reported to the active session and leave it usable; they do not complete the Host interaction. Cancel ends the Host interaction: dispose active session work, restore Origin or focus the editor group, restore prior Panel visibility, with the established focus ordering preserved. Successful completion runs the existing exit behavior after the Picker-specific effect. Behavior is unchanged for the user: file accept, grep accept, chooser-to-picker transition, cancel restore, and panel-visibility restore all behave as before.
